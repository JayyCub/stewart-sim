Context for Claude Code sessions in this repo. Read this first, then `docs/STATUS.md` for where things stand.

## What this is

A simulator and control stack for a hobby 6-DOF rotary Stewart platform: 6 × MG996R servos on a
PCA9685 driver, controlled by an Arduino Uno. One browser app designs the rig geometry, previews
motion before it runs on hardware, and later becomes a show-programming tool. It is also a
portfolio piece aimed at safety-critical embedded / simulation roles (aerospace and theme-park
ride systems), so verification, limits, and fault handling matter as much as features.

## Core rule

**One rig config, one set of test vectors.** Geometry, limits and servo calibration live only in
`packages/rig-config/rig.json`. The TypeScript kinematics and the future C++ firmware IK must both
pass `test-vectors/ik-v1.json`. Never hand-copy numbers from rig.json into firmware; generate a
header from it (planned: `firmware/stewart_uno/rig_config.h`).

## Layout

```
packages/kinematics/   Pure TS: IK, limit + collision checks, reach, tilt map, geometry sweep. No DOM.
packages/rig-config/   rig.json + validating parser (parseRigConfig) + defaultRig
apps/sim/              React 19 + react-three-fiber 9 + zustand app
test-vectors/          Golden pose -> horn angle cases (generated by scripts/gen-vectors.ts)
firmware/stewart_uno/  Arduino sketch (Phase 3, not started)
scripts/               gen-vectors.ts
docs/                  Plan, hardware, decisions, status
```

## Commands

Requires **Node 22** (`.nvmrc`; `nvm use`). Node < 20.19 fails with a `styleText` import error.

```
pnpm install
pnpm dev          # sim at http://localhost:5173
pnpm test         # vitest: unit tests + shared vectors (80 tests at last run)
pnpm typecheck    # tsc across all packages
pnpm build        # static build to apps/sim/dist (relative base, works on GitHub Pages)
pnpm vectors      # regenerate test-vectors/ik-v1.json after an INTENTIONAL IK change
```

Run `pnpm typecheck && pnpm test` before considering any change done.

## Conventions

- Lengths in **mm**. Kinematics API angles in **radians**; rig.json and UI use **degrees**.
- **z up.** Base frame origin = base centre at servo-shaft height. Platform frame origin =
  top-plate centre at top-ball-joint height.
- Pose = `{x, y, z, roll, pitch, yaw}` relative to home; `R = Rz(yaw)·Ry(pitch)·Rx(roll)`
  (three.js Euler order `"ZYX"`). Home (all zero) = every horn level.
- Legs indexed **0–5 in code**, shown as **1–6 in the UI**. Servo pair k (k = 0,1,2) holds legs
  2k and 2k+1, centred at k × 120°. Leg 2k is at `centre − halfAngle` and its horn points toward
  decreasing angle; leg 2k+1 mirrors it.
- Horn angle `alpha` is measured from level; positive raises the horn tip. Mirrored servos are
  handled by `servos[i].direction` in rig.json, not in the kinematics.
- Collision checks are opt-in: `solve(..., col)`. The shared test vectors and the firmware port
  cover IK + joint limits only; collisions are a sim-side design check.
- Ball-joint limit model: swivel = tilt of the rod away from perpendicular to the ball's stud.
  Bottom stud axis = servo shaft (radial). Top stud axis = radial in the platform frame.
- IK per leg (closed form): `alpha = asin(L / sqrt(M² + N²)) − atan2(N, M)` with
  `L = |l|² − (s² − a²)`, `M = 2a·l_z`, `N = 2a(cosβ·l_x + sinβ·l_y)`, `l = P − B`.

## Working agreements

- Limits are data, not code: anything physical comes from rig.json, ideally measured.
- Nothing unvalidated reaches hardware: the app must refuse motions that fail limit checks, and
  firmware clamps again.
- Each phase ends with something usable on its own (see "Done when" in the plan).
- If you change IK behaviour on purpose, regenerate vectors and say so in the commit message.
- Keep `packages/kinematics` free of DOM/React/three imports so it stays portable and testable.
- `scripts/` loads kinematics with Node's type stripping: no enums, namespaces or constructor
  parameter properties in `packages/`.

## Gotchas

- rig.json is still **placeholder values** (`"measured": false`). Don't treat reach numbers as
  real until the Phase 0 measurements are in.
- Web Serial (Phase 3) only works in desktop Chrome/Edge.
